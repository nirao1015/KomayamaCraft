# TASK-M00-06 カタログと検証

## 目的

ゲームで使用する定義を一元的に取得し、重複ID、参照切れ、不正値をビルド前に発見できるようにする。

## 参照仕様

- `spec/KomayamaCraft_ゲーム基本仕様.md`
- TASK-M00-01で作成するデータ基盤仕様

## 依存タスク

- `TASK-M00-02_アイテム定義.md`
- `TASK-M00-03_レシピ定義.md`
- `TASK-M00-04_設備と資源発生点定義.md`
- `TASK-M00-05_解放条件定義.md`

## 作業範囲

- アイテム、レシピ、設備、資源発生点、解放定義を参照する新作共通カタログを実装する。
- 起動時の検索や`Resources.LoadAll`へ依存せず、Inspectorで明示的にカタログを構成する。
- 永続IDから定義を取得する読み取り専用APIを用意する。
- Editorメニューから全定義を検証できるツールを作る。
- 少なくとも次を検出する。
  - 空または形式違反のID
  - 種別内・全体方針に反する重複ID
  - null参照
  - 存在しない参照ID
  - 0以下の数量、容量、時間
  - 空のレシピ入力・出力
  - 解放条件の循環参照
- エラーには対象アセットと修正理由を表示する。
- M1で利用する検証データ一式をカタログへ登録する。

## 対象外

- 実行時のアセット自動探索
- Addressables導入
- Steam向けビルド処理
- バランスの良し悪しを判定する検証

## 完了条件

- [x] 全定義を永続IDから取得できる。
- [x] 正常データでは検証が成功する。
- [x] 重複ID、参照切れ、不正値をEditor上で特定できる。
- [x] エラー対象のアセットをログから選択できる。
- [x] カタログ未登録の検証データを検出できる。
- [x] ビルドに必要な定義が明示参照で同梱される。

## 確認方法

1. 正常な検証データで全件検証を実行する。
2. ID重複、null参照、不正数量、循環参照を順に作る。
3. 各問題が対象アセット付きで報告されることを確認する。
4. 修正後に検証が成功することを確認する。

## 実装メモ

Editor専用検証コードは`Assets/Editor/`またはEditor専用asmdef配下へ置き、製品ビルドへ含めない。

## 成果物

- `Assets/Editor/KomayamaCraft/KomayamaGameDataValidator.cs`
  - 各カタログ自身の検証に加え、全定義ID重複、カタログ登録、定義間参照、文字列ID、解放前提と循環参照を横断検証する。
  - `AssetDatabase`に依存しない入力・結果APIへ主要ロジックを分離し、テストから直接呼び出せる。
- `Assets/Editor/KomayamaCraft/KomayamaGameDataValidationMenu.cs`
  - `Tools/KomayamaCraft/Game Data/Validate All`から全件検証を実行する。
  - エラーごとに対象`UnityEngine.Object`をConsoleログのcontextへ設定する。
  - ビルド前に同じ検証を実行し、エラー時は`BuildFailedException`で停止する。
- 明示参照カタログ
  - `Assets/Resources/GameData/Komayama*Catalog.asset`の5カタログから、M1検証用の全7定義を参照する。

## 保留

- 実行時の自動探索、Addressables、Steam固有ビルド処理はタスク対象外のままとする。
- 意図的な不正アセットを保存して行うエラーケース別の手動確認は、正常データを壊さないため未実施。検出分岐は共通検証ロジックに実装済み。
