# TASK-M00-01 永続IDとデータ規約

## 目的

ゲームデータとセーブデータを長期間安全に参照するため、表示名やファイル名から独立した永続IDとデータ作成規約を確定する。

## 参照仕様

- `spec/KomayamaCraft_ゲーム基本仕様.md`
- `spec/Unity_初期プロジェクト設定.md`

## 依存タスク

- なし

## 作業範囲

- 定義データ用IDと、配置物などの実体用IDを区別する。
- 定義IDは文字列とし、次の接頭辞を使用する。
  - `item.`
  - `recipe.`
  - `facility.`
  - `resource_node.`
  - `unlock.`
- 接頭辞以降は英小文字、数字、アンダースコアだけを使用する。
- 定義IDは公開後に変更しない。表示名、画像、ファイル名の変更ではIDを変えない。
- 配置設備、地面アイテム、資源発生点など、同じ定義から複数生まれる実体には別の一意なinstance IDを持たせる。
- ID変更が避けられない場合の旧ID対応表とセーブ移行規約を定義する。
- null、空文字、重複ID、存在しない参照の扱いを定義する。
- 規約を新規データ基盤仕様へ記録する。

## 対象外

- アイテムやレシピの具体的なパラメーター
- セーブファイルへの書き込み処理
- ローカライズシステム本体

## 完了条件

- [x] すべての定義種別で同じ形式の永続IDを使用できる。
- [x] 定義IDとinstance IDの用途が文書化されている。
- [x] ID変更・廃止時の移行方針が定義されている。
- [x] 不正IDを検出する共通検証方法が決まっている。
- [x] M00-02以降が参照できるデータ規約仕様が`spec/`に存在する。

## 確認方法

1. 正常、空、形式違反、重複のサンプルIDを用意する。
2. それぞれの判定結果が規約どおりになることを確認する。
3. 表示名やアセット名を変更しても永続IDが変わらない設計であることを確認する。

## 実装メモ

セーブデータにはUnityアセットのGUIDや表示名を直接保存しない。定義は永続ID、フィールド上の実体はinstance IDで参照する。
