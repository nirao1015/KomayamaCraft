# KomayamaCraft 自動化プレイテスト 詳細仕様

> **状態**：設計確定（レビュー回答反映）。**実装しない**（別指示まで）。
> **入口**：`KomayamaCraftDebugManager`（本番リリース用 ON では無効）。

---

## 0. 文書の位置づけ

| 項目 | 内容 |
| --- | --- |
| 目的 | 人手プレイなしで、クエスト進行に必要な操作を**疑似入力**で通し、進行・納品・解放が壊れていないかを確認する |
| 非目的 | ユニットテスト、セーブ改ざんによる進行スキップ、施設内部 API を直接叩いて結果だけ作ること |
| 関連 | 施設加工操作・建設・クエストログ・入力操作の各詳細仕様。クエスト台帳（カテゴリ含む）はクエスト設計文書が正本 |
| 値の書き方 | **確定**／**提案**／**後続定義** |

---

## 1. やりたいこと（要約）

開発中に、次の 2 モードで「プレイヤーがやっているのと同じ操作経路」を自動再生できる。

| モード | 内容 | 区分 |
| --- | --- | --- |
| **メインのみ** | **メインクエストカテゴリ**のクエストだけを完走する | 確定 |
| **全部** | メイン＋サブ等を含む対象クエストを完走する（消化順は §6.2） | 確定 |

操作は「内部関数で在庫を足す／クエスト完了フラグを立てる」ではなく、

- マウスを対象の上へ重ねた扱い
- 左／右クリックした扱い（メニュー UI 上のボタン選択含む）
- 納品操作をした扱い（納品先の種類ごとの正規手順。NPC 納品の詳細は後続定義）

として、**既存の入力・インタラクト経路と同じ口**を通す。

採集発生点・生産施設・納品先などは、自動テストが「どこを指して何をクリックしたか」を決められるよう、**テスト受け入れ口**を持つ。

## 2. 原則

### 2.1 疑似入力原則（確定）

| 原則 | 内容 |
| --- | --- |
| 同じ経路 | 採集・拾い・投入・メニュー開閉・レシピ選択・建設・納品は、通常プレイと同じコントローラ／インタラクト処理を通る |
| 疑似ポインタ | 実マウスの代わりに、ワールド座標または UI 座標の**仮想ポインタ**を置き、押下／解放／長押しを発行する |
| 禁止 | 進行だけを飛ばすデバッグ完了 API、施設の入力直叩き、クエスト完了フラグの直書き（※失敗時の診断用ログは可） |
| 許可する補助 | **カメラの対象付近への自動追従**、シナリオの次ステップ指定。**ゲーム状態の捏造はしない** |
| 時間加速との分離 | ゲーム全体の倍速は DebugManager の**独立機能**（§2.3）。自動化プレイテストはそれを**変更・操作しない** |

### 2.2 DebugManager 上の位置（確定）

| 項目 | 内容 |
| --- | --- |
| 置き場 | `KomayamaCraftDebugManager` に「自動化プレイテスト」セクション |
| 本番 | `本番リリース用` ON のときは起動不可・実行中なら即停止 |
| UI | Inspector からモード選択＋開始／停止。オーバーレイに状態（現在クエスト・ステップ・失敗理由）を出す（提案） |
| 実行形態 | Play Mode 中のコルーチン／ステップ実行。CI 常駐は後続 |

### 2.3 ゲーム倍速・一時停止（確定）

| 項目 | 内容 | 区分 |
| --- | --- | --- |
| 正本 | `KomayamaGameClock` → `Time.timeScale` | 確定 |
| デバッグ倍率 | 0.5 / 1 / 3 / 5 / 10（`DebugCanvas/ButtonSpeed`） | 確定 |
| 効くもの | `Time.deltaTime` / `WaitForSeconds` を使うもの全般（生産進行、ドロップ演出、Ghost 移動、施設ワールド進捗、狐のコマ送り等） | 確定 |
| 意図的に等速のまま | カメラ WASD、入力の長押し連打、UI スライド、トースト表示時間、オートセーブ、狐のカーソル追従 | 確定 |
| 一時停止 | `PushPause` / `PopPause`（イベント用・入れ子可）。デバッグは `ButtonPause` でトグル | 確定 |
| 自動化テスト | 倍速・一時停止を自動ではいじらない | 確定 |

## 3. 全体構成（概念）

```text
[DebugManager]
   ├─ ゲーム倍速（0.5 / 1 / 3 / 5 / 10）……自動化からは操作しない
   └─ AutoPlaytestRunner（モード選択・開始停止・レポート）
         ├─ VirtualPointer（疑似マウス：位置・Hover・Click・Hold／UI クリック）
         ├─ ScenarioPlayer（クエスト手順を順に消化）
         └─ TargetResolver（定義 ID／Marker／進行中目標から対象解決）

[各システムが備えるテスト受け入れ口]
   採集発生点 / 地面ドロップ / 加工施設 / 仮組・建設 / 保管 / メニュー UI / 納品先
         └─ インタラクト点・受け付け操作・操作可能かの宣言（状態捏造 API ではない）
```

## 4. 疑似ポインタ

### 4.1 能力（確定）

| 操作 | 意味 |
| --- | --- |
| MoveToWorld / MoveToUi | 仮想カーソルを移動（Hover 扱い） |
| LeftDown / LeftUp / LeftClick | 左ボタン |
| RightDown / RightUp / RightClick | 右ボタン |
| HoldLeft / HoldRight | 長押し（採集連打・連続投入・なぞり拾い） |
| WaitUntil / WaitSeconds | 条件待ち・固定待ち |

### 4.2 入力差し込み（確定方針）

ワールド操作とメニュー UI の両方を疑似クリックするため、次を組み合わせる。

| 層 | 内容 | 区分 |
| --- | --- | --- |
| ワールド | `KomayamaCraftInputController` が実マウスまたは仮想ポインタを読む | 確定 |
| UI | 開いているメニュー上のボタン／レシピ枠へ `MoveToUi`＋クリック（EventSystem 経路または同等） | 確定 |

施設メニューを開き、レシピを選ぶところまで自動化する（動作テストも兼ねる）。ショートカットだけでレシピを飛ばさない。

### 4.3 カメラ（確定）

仮想クリック前に、対象が操作できるよう**カメラを対象付近へ自動追従**する。カメラ手動操作そのものの再現は必須としない。

## 5. テスト受け入れ口

### 5.1 共通概念（提案名：`IAutoPlaytestTarget`）

| 公開するもの | 意味 | 区分 |
| --- | --- | --- |
| `TargetId` | 安定 ID（定義 ID／instance ID／エイリアス） | 確定 |
| `GetInteractWorldPoint()` | 疑似ポインタを重ねるワールド座標 | 確定 |
| `SupportedActions` | 左／右／長押しなど、受け付ける操作 | 確定 |
| `IsInteractableNow` | 今クリックして意味があるか | 確定 |
| （任意）`DescribeState()` | 失敗時ログ用 | 提案 |

**やらないこと**：`ForceComplete()` / アイテム直加算などの進行捏造。

### 5.2 UI 受け入れ口（確定）

メニュー系はワールド点に加え、次を公開する。

| 公開 | 意味 |
| --- | --- |
| レシピ選択枠の UI 座標／要素 | 疑似クリックでレシピを選ぶ |
| 排出・レシピ変更・閉じる等のボタン | 必要なステップで疑似クリック |
| 建設メニューの候補ボタン | 施設種選択 |

### 5.3 対象種別ごとの口

| 種別 | 疑似操作で再現する行為 | 区分 |
| --- | --- | --- |
| 採集発生点 | 左クリック／長押し採集 | 確定 |
| 地面ドロップ | 左クリック拾い／なぞり | 確定 |
| 加工施設 | 左＝メニュー（ドロップ優先は既存仕様）、右＝投入。メニュー内でレシピ選択 | 確定 |
| 仮組施設 | 右＝建設素材投入 | 確定 |
| 建設 UI＋配置 | メニュー操作＋配置ワールド点をクリック | 確定 |
| 保管 | 左取出・右格納 | 確定 |
| 納品先 | 正規の納品操作（掲示板／船等は既存仕様。**NPC 納品は後続定義**） | 確定／後続 |
| ゴミ箱 | 右で納入 | 提案 |

### 5.4 対象の解決（確定）

| 解決キー | 用途 | 区分 |
| --- | --- | --- |
| 定義 ID | 発生点・施設種など | 確定 |
| インスタンス ID | 同種が複数あるとき | 確定 |
| **シーン Marker**（`AutoPlaytestMarker`） | **建設配置点・固定インタラクト地点の正** | 確定 |
| クエスト目標バインド | 進行中クエストが指す納品先など | 提案（台帳連携後） |

#### 建設位置（確定）

**シーン上の名前付き Marker を正**とする。

- 座標ベタ書きはシーン変更に弱い。
- Marker は「ここに置く」意図がシーン上で見える。
- シナリオは `MarkerId` を参照し、そのワールド座標へ疑似クリックして配置する。

## 6. シナリオとモード

### 6.1 シナリオの単位（確定）

| 単位 | 内容 |
| --- | --- |
| クエスト手順 | 1 クエスト＝複数ステップ |
| ステップ | 1 疑似操作、または条件待ち（UI クリック含む） |
| 成功条件 | クエスト進行・手持ち・施設状態など**観測可能な状態** |

### 6.2 モードと消化順（確定）

| モード | 消化対象 |
| --- | --- |
| MainOnly | **メインクエストカテゴリ**のみ |
| All | メイン＋サブ等 |

**All の優先（確定）**

1. **サブを優先**して消化する。
2. サブの次ステップに必要な素材がまだ手に入らない、対象が未解放など**今は進めない**と判断したら、そのサブは一旦保留し**メインへ移ってよい**。
3. メイン進行で条件が揃い次第、保留サブへ戻る。

進行不能の定義（タイムアウト・対象なし・操作失敗の連続など）に達したら §8。

### 6.3 クエストカテゴリ（確定）

クエスト設計側に **メインクエストカテゴリ**を設ける（Debug 手順だけの暫定タグにはしない）。  
サブ等のカテゴリ詳細はクエスト設計文書に従う。自動化は台帳のカテゴリを読んで MainOnly / All を切り替える。

### 6.4 台帳と手順データ（提案）

| 段階 | 内容 |
| --- | --- |
| クエスト設計と並行 | 各クエスト（または目標タイプ）に自動テスト用ステップ／テンプレを紐づける |
| 未整備の間 | 手順 SO／JSON を暫定で持ってよいが、カテゴリは台帳の Main 定義に合わせる |

## 7. 実行フロー（確定）

1. Play Mode 中、**いまのゲーム状態のまま** DebugManager からモード選択→開始する（New Game 強制はしない。任意セーブ読込後の続きからも可）。
2. **チュートリアルも実施する**（自動スキップしない）。案内ステップも疑似操作／条件待ちで進める。
3. Runner がモードに従い「いま消化すべきクエスト」を決める（All は §6.2）。
4. ステップ列を順実行：
   - TargetResolver で対象／UI／Marker を解決
   - カメラ自動追従
   - VirtualPointer で Hover → Click／Hold（メニュー操作含む）
   - WaitUntil（タイムアウトあり）
5. クエスト完了を観測したら次へ。
6. 対象が尽きたら成功終了。
7. **進行不能**と判断したらメッセージを出し**即停止**（§8）。

## 8. 失敗・観測（確定）

| 項目 | 内容 |
| --- | --- |
| 進行不能 | ステップタイムアウト、対象解決失敗、必須 UI が無い、操作しても状態が進まない、など |
| 失敗時 | **メッセージを出して即停止**。次クエストへ続行しない |
| ログ | 現在クエスト／ステップ／最後の疑似操作／理由 |
| スクリーンショット | 失敗時のみ（提案） |

---

## 9. 既存仕様との接点

| 既存 | 自動化での扱い |
| --- | --- |
| 施設上左クリック：ドロップ拾い ＞ メニュー | 疑似クリックも同じ優先 |
| 完成直後の右長押し投入禁止 | シナリオは離して再押下 |
| 生産完了は地面ドロップ | 完成待ちはドロップ出現または拾い成功を観測 |
| 契約・NPC 納品 | **NPC 納品の正規手順は後続定義**。定義されるまで自動化ステップはプレースホルダ |
| ゲーム倍速 Debug | 手動設定可。自動化は触らない |
| RapidHoldDrop | 手動で併用可。自動化は必須としない |

## 10. チュートリアル（確定）

| 項目 | 内容 |
| --- | --- |
| 自動テスト時 | **チュートリアルもやる**（スキップ固定にしない） |
| 進め方 | 既存案内の完了条件を観測し、必要な疑似操作で進める |
| プレイヤーが T スキップ相当 | 自動化シナリオからは使わない（正規進行をテストする） |

## 11. 実装フェーズ（提案・未実装）

| 段階 | 内容 |
| --- | --- |
| P0 | VirtualPointer ＋ InputController。カメラ追従。採集→拾い→施設メニュー開く→レシピ選択→投入→完成拾い |
| P1 | DebugManager から現在状態で MainOnly 開始。失敗メッセージ即停止 |
| P2 | 建設（Marker 配置）。チュートリアル手順対応 |
| P3 | クエストカテゴリ連動。All（サブ優先・行き詰まりでメインへ） |
| P4 | 納品口（NPC 定義後）。ゲーム倍速 UI は別タスク |

## 12. レビュー回答の反映一覧

| 質問 | 確定内容 |
| --- | --- |
| 開始状態 | **いまの状態から開始**可能（New Game 強制なし） |
| 時間加速 | Debug に 0.5／1／3／5／10 倍を用意。**自動化はいじらない** |
| カメラ | **自動追従してよい** |
| メイン／サブ | クエスト設計で**メインクエストカテゴリ**を作る |
| All の順 | **サブ優先**。進めなければメインへ移ってよい |
| 建設位置 | **シーン Marker を正**（おまかせ回答） |
| メニュー UI | **開いてレシピ選択まで自動化必須** |
| 失敗時 | **進行不能ならメッセージ＋即停止** |
| チュートリアル | **やる**（スキップ固定にしない） |
| NPC 納品 | **NPC 納品設計時に再定義** |

### 後続で残すもの

- NPC 納品の正規操作シーケンス（自動化ステップへの落とし込み）
- サブカテゴリの細分、同時複数サブのキュー詳細
- CI からのヘッドレス実行の要否
