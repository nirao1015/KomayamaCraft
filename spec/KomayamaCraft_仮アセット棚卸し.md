# KomayamaCraft 仮アセット棚卸し（フェーズ5）

> **状態**：判断反映済み。差し替え作業はリソースチェーン確定後にまとめて行う。  
> **方針**：定義ID・questId は変えず、**見た目（Sprite／表示名）だけ**差し替える。アセットファイル名は人間が読める名前を維持する（`item01` 等の ID 直結命名は採用しない）。

関連：永続ID規約、指示差分と数値、クエスト会話書き方。

---

## 1. ルール（確定）

| # | 規則 |
| --- | --- |
| 1 | `item.*` / `facility.*` / `recipe.*` などの **定義IDは変えない** |
| 2 | 差し替えは ScriptableObject の `icon`／Prefab の Sprite／船 `stageSprites` の参照差替え |
| 3 | 後から差し替えても **ファイル名は同系統のまま**（参照付け替えで足りる） |
| 4 | スプライト／テクスチャのファイル名は **内容が分かる名前**（例：`drop_鉄鱗`、将来の鱗鉄板名）。`item01` や定義IDそのままの連番命名は避ける |
| 5 | 定義ID ↔ 見た目の対応はカタログ／SO 参照が正本。ファイル名から ID を推測させない |
| 6 | シナリオで世界観名が固まる前に、見た目の一括製作を始めない |

## 3. 製作タイミング（確定）

1. **リソースチェーン（素材名・工程・ID）を確定**する  
2. 世界観に揃えた見た目を **一気に製作**する  
3. 各定義の `icon`／Sprite 参照だけ付け替える（ID・レシピ・クエスト定数は触らない）  
4. チュートリアル関連を触ったら P0 常緑を 1 回通す  
5. 本表の「仮？」を更新する  

鱗鉄板はチェーン確定まで `tile_cog` のままでよい。

## 4. 命名の分け方（確定）

| 層 | 例 | 役割 |
| --- | --- | --- |
| 定義ID（永続） | `item.iron_scale_plate` | セーブ・レシピ・クエストが参照 |
| アセットファイル名 | `drop_鱗鉄板.png` など（製作時に決定） | 人が見て分かる。ID と一致させなくてよい |
| 表示名 | SO の `displayName`／将来は文言 ID | UI 表示 |
