## 2. セキュリティ（確定・必須）

本機能が読み取ってよいのは **テキスト辞書用 JSON のみ**である。

| 規則 | 内容 | 区分 |
| --- | --- | --- |
| 実行しない | JSON 内の文字列をコード・式・スクリプトとして実行しない | 確定 |
| 読まない | 辞書以外のファイル種別・任意パス・ネットワーク URL を読まない | 確定 |
| パス | 言語コードは **許可リスト**（公式＋一覧に載ったコード）のみ。`../` 等によるディレクトリ外参照は拒否 | 確定 |
| パース | 読み込み時に JSON として厳密にパースする。失敗したファイルは採用せず、ログしてフォールバック | 確定 |
| サイズ上限 | **一定サイズを超えるファイルは読み込まない**（上限バイト数は実装時に確定。提案：言語一覧 64KB、各辞書 2MB） | 提案／実装時確定 |
| 内容 | キーと文字列（および一覧用のメタ）以外の拡張フィールドは無視してよい。実行可能ペイロードを解釈する欄を設けない | 確定 |

「ユーザーが編集可能な場所に置く」ことと、「テキスト辞書以外を実行・読まない」ことは両立させる。

## 3. 翻訳対象と非対象

### 3.1 対象（カテゴリ分け・確定）

辞書・キーは次の区分で分ける（ファイル分割またはキー接頭辞のどちらか。実装時に選ぶ。**接頭辞案を提案**）。

| 区分 | 接頭辞案 | 例 | 区分 |
| --- | --- | --- | --- |
| UIラベル | `ui.` | ボタン、メニュー、設定項目名 | 確定（分け方）／提案（接頭辞） |
| アイテム名 | `item.*.name` | 鉄鱗、設備名など | 同上 |
| 説明 | `item.*.desc` / `facility.*.desc` 等 | ツールチップ、図鑑説明 | 同上 |
| クエスト | `quest.` | タイトル・本文・進捗文言 | 同上 |
| チュートリアル | `tutorial.` | 案内文 | 同上 |
| システムメッセージ | `sys.` | エラー、上限、無効操作など | 同上 |

### 3.2 非対象（確定）

| 対象 | 理由 |
| --- | --- |
| セーブ・定義の永続 ID | ロジックキー。翻訳しない |
| 画像に焼き込んだ文字 | **翻訳対象外**。必要ならテキスト UI 化するか、言語別スプライトを別途用意（本機能の範囲外） |
| デバッグ専用ログ | 任意。プレイヤー向けでなければ翻訳不要 |

## 4. ファイル構成と MOD

### 4.1 配置

```text
{persistentDataPath}/Localization/
  languages.json      … 対応言語一覧
  ja.json             … 日本語辞書（原典）
  en.json             … 英語辞書
  （ユーザー追加）xx.json …
```

- 初回起動時：パッケージ同梱の公式 JSON を上記フォルダへコピー（既存ユーザーファイルは上書きしない、またはキー単位マージ。**マージ規則は実装時確定。提案：ユーザーファイル優先でキー単位上書き**）。
- ユーザーは同フォルダを編集・ファイル追加して翻訳 MOD を作れる。

### 4.2 `languages.json`（案）

```json
{
  "version": 1,
  "languages": [
    { "id": "ja", "displayName": "日本語", "file": "ja.json", "official": true },
    { "id": "en", "displayName": "English", "file": "en.json", "official": true }
  ]
}
```

- 公式がシステムとして保証するのは **ja / en** のみ。
- 一覧に載った追加言語は MOD として読める（パース・サイズ・パス規則を満たす場合）。UI の言語選択に出す。

### 4.3 辞書 JSON（案）

```json
{
  "version": 1,
  "language": "ja",
  "entries": {
    "ui.build.title": "建設",
    "item.iron_scale.name": "鉄鱗",
    "sys.inventory_full": "手持ちがいっぱいです"
  }
}
```

- キーは **ID（英数字・`.`・`_`）**。日本語原文をキーにしない。
- 値は表示用文字列のみ。プレースホルダは実装時に `{0}` 形式などを確定する。

## 6. 公式英訳の作り方（制作ワークフロー・確定）

公式英語は次の手順で品質を確認する。

1. **原典は日本語**の JSON を正とする。
2. AI に翻訳させるとき、キーまたはメタで **UI か会話（クエスト／チュートリアル等）か**を伝え、トーンを分ける。  
   - UI：短く、ボタン向け、用語統一  
   - 会話・クエスト・チュートリアル：文として自然な訳
3. できた英語を、別パスで **英語→日本語へ再翻訳**させ、原典日本語と意味が一致するか検討する。
4. ずれが大きいキーは人手で直す。

このワークフローは制作パイプラインであり、ゲーム実行時には行わない。
