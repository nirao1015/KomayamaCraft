# 旧作資産撤去計画

## 1. 方針

新作の内部識別名は`KomayamaCraft`で固定し、メインフィールドシーン名は`komayama_craft_scene`とする。

旧game01、game02、game03の資産は新作へ引き継がない。ただし、旧作コードとシーンは相互参照が多いため、M1開始時に一括削除しない。新作の縦切りが単独で起動できる状態を先に作り、旧作依存を共有基盤から分離してから段階的に撤去する。

## 2. 保持する新作基盤

- `Assets/Scripts/GameData/KomayamaCraft/`
- `Assets/Editor/KomayamaCraft/`
- `Assets/GameData/KomayamaCraft/`
- `Assets/Prefabs/KomayamaCraft/`
- `Assets/Resources/GameData/Komayama*.asset`
- `spec/KomayamaCraft_ゲーム基本仕様.md`
- `spec/データ基盤_*.md`
- `spec/Unity_初期プロジェクト設定.md`

## 3. 条件付きで保持する共通基盤

次は新作でも利用価値があるが、旧作固有参照を除去してから使用する。

- 固定アスペクト表示
- 音量設定と共通セーブ
- フェード付きシーン遷移
- logo、title、dialogueの各シーン
- CSV会話基盤
- Steam初期化基盤
- 汎用フォント、BGM、SE、UI素材
- Input System設定
- URP 2D設定

第三者素材は利用規約とクレジット条件を確認できるまで削除しない。

## 4. 先に解消する危険な結合

### 固定アスペクト

`AspectSettingsBootstrap`は実行時にGameObjectとコンポーネントを追加しており、新作の実装規約に合わない。

新作シーンでは`FixedAspectCameraFitter`と`FixedAspectCanvasFitter`をInspectorで事前にアタッチする。新作シーンが自立した後、旧ランタイムブートストラップを停止・撤去する。

### フェード

`ButtonFadeSceneLoader`はgame02型を直接参照し、FadeManagerがない場合に実行時生成する。

新作で再利用する前にgame02依存を除去し、FadeManagerは起動シーンまたはPrefabへ事前配置する。新作コードから実行時`AddComponent`へ依存しない。

### 音量と共通進行

`SoundSettingsManager`の`playerData.json`には旧game01〜03のクリアフラグとデバッグ解放が含まれる。

音量処理と旧作進行を分離し、新作の共通設定だけを残す。既存セーブを読み込む場合はversion移行を用意し、旧フィールドが存在しても無視できるようにする。

### GameData

`GameDataCatalogs`には旧敵出現カタログと新作カタログが同居している。

旧ゲームコード撤去時に旧カタログの読み込み口を削除する。`GameDataCatalogSync`も旧敵出現データを再生成しない新作向け構成へ分離する。

### タイトルと会話

現行タイトルはgame01〜03の解放チェーンを前提とし、会話は旧シーン名を既定値としている。

新作のタイトル入口を`komayama_craft_scene`へ接続し、会話を使用する場合は新作用の明示的な遷移先とCSVキーを設定する。旧シーン名へのフォールバックは残さない。

### Steam

旧実績IDと旧ゲームの解除処理を新作から参照しない。Steam APIが利用できない場合でも新作本体を開始できる構造は維持する。

## 5. 撤去手順

### Phase 1：新作縦切りの独立

1. `Assets/Scenes/komayama_craft_scene.unity`を作成する。
2. Main Camera、Canvas、EventSystem、固定アスペクトコンポーネントをシーンへ事前配置する。
3. Build Settingsの末尾へ新作シーンを追加する。
4. 旧シーンは有効のまま維持し、新作シーンを直接開いて開発する。
5. M1の採集から加工品回収までを新作コードだけで成立させる。

### Phase 2：共有基盤から旧作依存を分離

1. `ButtonFadeSceneLoader`からgame02依存と実行時生成を除去する。
2. 音量設定から旧作進行フラグを分離する。
3. タイトルに新作入口を追加する。
4. 会話の既定遷移先を新作向けに変更する。
5. GameDataとSteamの旧作参照を分離する。

### Phase 3：旧作をビルド対象外にする

新作のタイトルからフィールドまで遷移できることを確認した後、次をBuild Settingsで無効化する。

- `menu_scene`
- `game_stage_scene`
- `menu02_scene`
- `game02_scene`
- `menu03_scene`
- `game03_scene`

logo、title、dialogueは新作向け修正が完了したものだけ残す。

### Phase 4：旧作資産を物理削除する

1. game03のシーン、スクリプト、Prefab、GameDataを削除する。
2. game02のシーン、スクリプト、Prefab、GameDataを削除する。
3. game01のシーン、スクリプト、Prefab、敵コード、GameDataを削除する。
4. 旧敵出現カタログと同期処理を削除する。
5. 旧作専用の画像、音、Shaderを参照確認後に削除する。
6. 各段階でコンパイル、データ検証、Windowsビルドを確認する。

### Phase 5：Project Settingsを整理する

旧Prefabと旧シーンからレイヤー7〜13の使用がなくなったことを確認してから、旧レイヤーを整理する。

Sorting LayerとPhysics 2Dの衝突マトリクスは、新作フィールドの実際の描画順・Collider構成を基準に確定する。

## 6. 削除前の必須確認

- 旧シーン名を参照する新作コードがない。
- 残すシーンにMissing Scriptがない。
- `Tools/KomayamaCraft/Game Data/Validate All`が成功する。
- Consoleのコンパイルエラーが0件である。
- 新作シーンを直接起動してM1の縦切りを完了できる。
- logoから新作までの遷移を確認できる。
- 新作セーブを保存・復元できる。
- Steam API失敗時も新作を開始できる。
- Windows Standaloneビルドが起動する。

## 7. 保留事項

- 正式な表示タイトル
- Product Name
- Application Identifier
- Bundle Versionの正式な番号体系
- 旧logo、title、dialogueの見た目を流用するか、新規作成するか
- 旧BGM、SE、画像の利用範囲

内部識別名`KomayamaCraft`、保存ファイル名`komayamaCraftData.json`、メインフィールドシーン名`komayama_craft_scene`は今後変更しない。
