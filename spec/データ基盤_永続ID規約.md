# データ基盤：永続ID規約

## 1. 目的

本書は、ゲームデータとセーブデータを安定して関連付けるためのID規約を定める。

表示名、ファイル名、UnityアセットのGUID、Hierarchy上の名前は制作中に変更される可能性があるため、ゲーム上の永続参照には使用しない。

## 2. IDの分類

### 2.1 定義ID

定義IDは、アイテムやレシピなど「何の種類であるか」を示す。

同じ種類から複数の実体が生成されても、定義IDは共通である。たとえば、地面に鉄鱗が10個存在する場合、10個すべてが同じアイテム定義IDを参照する。

定義IDはScriptableObjectなどの定義データに文字列として保存し、次の用途で使用する。

- 定義データ同士の参照
- カタログからの定義取得
- セーブデータから定義を復元する際の参照
- 解放条件や進行条件の対象指定
- デバッグ表示とデータ検証

### 2.2 instance ID

instance IDは、フィールド上に存在する個別の実体を識別する。

同じ設備定義から作られた設備、同じアイテム定義から生まれた地面アイテムであっても、それぞれ異なるinstance IDを持つ。

instance IDを必要とする対象は次のとおり。

- 配置済み設備
- 地面に存在するアイテム
- 状態を個別保存する資源発生点
- 稼働状態を個別保存する自動作業者
- 個別の参照元・配送先・加工元として指定される実体

手持ちやチェスト内で同種アイテムを数量だけで管理する場合、スタックごとのinstance IDは必須としない。

## 3. 定義IDの形式

定義IDは次の形式とする。

```text
<種別接頭辞>.<識別名>
```

初期段階で使用する種別接頭辞は次のとおり。

- アイテム：`item.`
- レシピ：`recipe.`
- 設備：`facility.`
- 資源発生点：`resource_node.`
- 解放項目：`unlock.`
- クエスト：`quest.`（セーブ `questProgress.questId`。移行は保存データ契約 §11.1）

有効な定義IDの例：

```text
item.iron_scale
item.bio_gasket
recipe.iron_scale_plate
facility.scale_press
resource_node.iron_scale_creature
unlock.tier_02
quest.main_rain_leak
quest.main_refuel_bench
```

形式判定は次の正規表現と同等とする。

```text
^(item|recipe|facility|resource_node|unlock|quest)\.[a-z][a-z0-9_]*$
```

規則は次のとおり。

- ASCII英小文字、数字、アンダースコア、接頭辞直後のピリオドだけを使用する。
- 識別名の先頭は英小文字とする。
- 空白、日本語、大文字、ハイフン、連続する区切り記号は使用しない。
- 比較には大文字小文字を区別するOrdinal比較を使用する。
- IDはプロジェクト全体で一意とする。
- Tier番号を含める場合は`tier_01`のように2桁で表す。

## 4. 定義IDの不変性

一度セーブデータから参照される可能性が生じた定義IDは、原則として変更しない。

次を変更しても定義IDは変更しない。

- 表示名
- 説明文
- アイコン
- アセットのファイル名
- アセットの保存フォルダ
- UnityアセットのGUID
- Prefab名
- ゲームバランス値

廃止したIDを別の意味で再利用してはならない。以前のセーブデータが、新しい別物へ誤って復元されるためである。

正式リリース前であっても、テスト用セーブを継続利用する期間に入った後は同じ規則を適用する。

## 5. instance IDの形式と生成

instance IDはUUID v4相当の128bitランダム値とし、ハイフンなし・英小文字の32文字で保存する。

例：

```text
6f9619ff8b8646d0a88f4b8f6f30b2a1
```

生成と維持の規則は次のとおり。

- 実体を新規生成した時点で1度だけ発行する。
- セーブから復元した実体は、保存されていたinstance IDを維持する。
- ロード、シーン再表示、オブジェクトの有効・無効切替では再発行しない。
- 配置設備を移設しても再発行しない。
- 設備を撤去し、新しい設備として建設し直した場合は新規発行する。
- 実行時初期化で、設定済みinstance IDを上書きしない。

シーンへ事前配置する永続対象は、Editor上でinstance IDを発行してシリアライズする。複製によって同じIDが生じた場合は、Editor検証で重複を検出し、複製側へ新しいIDを発行する。

## 6. 参照規則

### 6.1 データ間参照

定義データ間の保存可能な参照は、定義IDを正とする。

Inspector上でScriptableObjectを直接参照する場合も、ビルド前検証では参照先の定義IDが有効で一意であることを確認する。セーブデータにはScriptableObject、UnityアセットGUID、ファイルパスを保存しない。

### 6.2 実体間参照

配送先設備、加工中設備など、フィールド上の特定実体を指す場合はinstance IDを使用する。

一時的にしか必要ない参照は実行時のオブジェクト参照を使用してよいが、セーブをまたいで復元する必要がある参照はinstance IDへ変換する。

### 6.3 名前による解決の禁止

表示名、GameObject名、アセット名から定義や実体を自動解決しない。IDが見つからない場合に名前検索へフォールバックしてはならない。

## 7. 定義IDの変更と移行

やむを得ず定義IDを変更する場合は、セーブversionごとの明示的な移行処理で旧IDを新IDへ変換する。

移行対応表は次の情報を持つ。

- 変更前ID
- 変更後ID
- 適用するセーブversion
- 変更理由

移行規則は次のとおり。

- 1つの旧IDは1つの新IDだけへ対応させる。
- 同じ旧IDを複数の移行規則へ登録しない。
- `A → B → C`の連鎖を常態化させず、古いversionから現在versionへ段階的に移行する。
- 移行後のIDが現行カタログに存在することを検証する。
- 移行先が存在しない状態ではセーブversionを更新しない。
- 単なる表示名変更では移行を作成しない。

定義を完全に廃止する場合は、代替IDへ変換するか、安全に削除できるデータ種別であることを移行処理へ明記する。

## 8. 不正値の扱い

### 8.1 制作時

次の状態はビルドを止めるエラーとして扱う。

- nullまたは空の定義ID
- 形式に違反する定義ID
- 重複した定義ID
- 存在しない定義IDへの参照
- nullの必須参照
- 重複したinstance ID
- 移行対応表の重複、循環、存在しない移行先

具体的なEditor検証ツールは`TASK-M00-06_カタログと検証.md`で実装する。

### 8.2 セーブ読み込み時

セーブ内のIDを名前や配列番号へ推測変換しない。

処理順は次のとおり。

1. セーブversionに対応する明示的なID移行を適用する。
2. 現行カタログから定義IDを解決する。
3. 解決できないレコードは警告として記録し、そのレコードだけを実行時状態へ復元しない。
4. 元のセーブファイルまたはバックアップは保持し、読み込み直後に未知IDを失った内容で自動上書きしない。
5. 必須進行データを解決できない場合は、安全な初期状態へ補完したことを明示する。

未知IDがあってもゲーム全体をクラッシュさせない。ただし、問題を隠すために別の定義へ置き換えない。

## 9. 共通検証APIの要件

M00-06で実装する共通検証APIは、少なくとも次を提供する。

- ID文字列の形式判定
- 期待する種別接頭辞の判定
- 複数定義の重複判定
- 参照先IDの存在判定
- instance IDの形式判定
- instance IDの重複判定
- 人が修正できるエラーメッセージ

形式判定はゲーム固有の各定義クラスへ重複実装せず、共通コードへ集約する。

## 10. 判定例

有効：

- `item.iron_scale`
- `recipe.tier_01_hull_scale`
- `facility.bio_assembly_tank`
- `resource_node.heat_sac_plant`
- `unlock.tier_02`

無効：

- 空文字：IDがない
- `IronScale`：接頭辞がなく大文字を含む
- `item.IronScale`：大文字を含む
- `item.鉄鱗`：ASCII以外を含む
- `item.iron-scale`：ハイフンを含む
- `item.01_iron_scale`：識別名が数字で始まる
- `enemy.iron_scale_creature`：未定義の接頭辞

同じ有効IDが2つのアセットへ設定されている場合は、両方とも形式上は有効だが、カタログ全体の重複エラーとする。

## 11. 後続タスクへの適用

- M00-02以降のすべての定義は本規約の定義IDを持つ。
- M00-06は本規約に従うEditor検証を実装する。
- M00-07は定義IDとinstance IDを使う保存DTOを定義する。
- M1以降のフィールド実体は、保存対象になる時点からinstance IDを保持する。
- 新しい定義種別を追加する場合は、使用開始前に接頭辞を本書へ追加する。
